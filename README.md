# bacain_chatbot — Discord Link-Analysis Bot

[![CI](https://github.com/SulthanZahran1/bacain_chatbot/actions/workflows/ci.yml/badge.svg)](https://github.com/SulthanZahran1/bacain_chatbot/actions/workflows/ci.yml)
[![CD](https://github.com/SulthanZahran1/bacain_chatbot/actions/workflows/cd.yml/badge.svg)](https://github.com/SulthanZahran1/bacain_chatbot/actions/workflows/cd.yml)

When a user posts a URL in a configured channel, the bot fetches the article,
classifies it, runs a **coverage-feedback search loop** across fresh sources,
synthesizes a multi-angle analysis, and replies in a thread — with **every
citation mechanically verified against the actual fetched corpus**.

Built to spec (`goal.md`): Rust workspace, TinyFish Fetch (the **only**
URL-retrieval path — the bot never fetches raw URLs itself, SSRF-safe),
Exa search (pooled keys, TinyFish Search fallback), any OpenAI-compatible LLM
(default: Ollama Cloud `deepseek-v4.1-flash`).

## Provider resilience

Three independent failure surfaces, each with a fallback so a single dead
credential or a single odd model answer cannot take the bot down:

| Layer | Primary | On failure |
|---|---|---|
| Search | Exa, rotating across an ordered **key pool** | TinyFish Search (`FallbackSearchProvider`) |
| Fetch | TinyFish Fetch | — (only retrieval path by design) |
| LLM | Ollama Cloud | secondary OpenAI-compatible provider (`LLM_FALLBACK_*`) |

**Exa key pool** (`EXA_API_KEY` may be a comma-separated list, then
`EXA_API_KEY_2` .. `EXA_API_KEY_9`): the first healthy key is used, and a key
that answers with a billing/quota (402) or rate-limit (429) error is parked
for an hour while the next slot takes over. A malformed request (400) does not
rotate — it would fail on every key, and rotating would only burn quota.
Mirrors the Hermes `exa-pool` plugin convention.

**Synthesis shape tolerance**: models occasionally answer a declared string
field with an array of bullets (exactly what the prompt asks for). That is
coerced (array → newline-joined text) before deserialization, instead of
hard-failing the analysis with `invalid type: sequence, expected a string`.

## Architecture

```
crates/
  core/   pure pipeline (no Discord): fetcher → classifier → search loop →
          reader → synthesizer → citation validator; scenario suite; optimizer
  bot/    serenity gateway: gates, ⏳+thread UI, slash commands, rendering
```

### Pipeline (single async entry: `pipeline::analyze`)

1. **Fetch** source via TinyFish Fetch (markdown). Errors map to §10 taxonomy.
2. **Classify** AI vs non-AI: keyword score; ambiguous band (1–3 hits) → LLM
   disambiguation (non-fatal on failure). AI topic → **30-day window override**.
3. **Window**: domain-speed buckets (breaking 3d / fast 7d / standard 30d /
   slow+regulatory 90d / evergreen ∞), overridable via `DOMAIN_SPEED_JSON`.
4. **Search loop**: seed queries from source → search (pooled Exa, TinyFish
   Search fallback) → batch-fetch hits → coverage assessment (distinct angles
   covered / ground truth) → expand with new angles until target, budget,
   diminishing returns, max rounds, or the 60 s deadline.
5. **Read**: token budget (default 60k), source gets 50 %, head+tail trimming.
6. **Synthesize**: LLM writes summary + deep analysis + critique with
   citations; JSON repair retry once.
7. **Validate citations**: pool = {source} ∪ {successfully fetched hits};
   anything else is **pruned** (hallucination-injection tested).

### Search-loop policy (env wins > `optimized_policy.json`)

`INITIAL_K` (default 5), `EXPANSION_K` (2), `COVERAGE_TARGET` (0.9),
`MIN_NEW_ARTICLES` (0), `MAX_ROUNDS` (4), `SEARCH_BUDGET` (20). The shipped
`optimized_policy.json` is the winner of a 972-cell offline sweep over the
101-scenario suite (utility = angles − wasted-fetch penalty − overshoot
penalty).

## Quick start

```bash
cp .env.example .env   # fill DISCORD_TOKEN, TINYFISH_API_KEY, EXA_API_KEY, LLM_API_KEY
cargo build --release
./target/release/linkbot-bot
# or:
docker compose up --build -d
```

Invite the bot to a server, allowlist a channel (`ANALYZE_CHANNELS`), post a
URL. Slash commands: `/analyze <url>` (force), `/status`, `/config`, `/ping`.

## Verification (DoD §15)

```bash
cargo test                # 240+ tests: unit + integration + 101-scenario suite
cargo clippy --all-targets -- -D warnings
cargo fmt --check
cargo build --release
./scripts/test_ratio.sh   # test:code ≥ 1:1 (code lines, tokei-style)
cargo mutants -p linkbot-core  # ≥80% mutation score
cargo run --release -p linkbot-core --bin optimize  # re-run policy sweep
```

Scenario suite: 101 synthetic scenarios (AI/non-AI × every bucket × dense/
sparse/dead/dup/rate-limit/adversarial/staleness) generated by
`crates/core/scripts/generate_scenarios.py`, run against the **real** pipeline
code with mocked search + scripted LLM (fully offline, deterministic).

## Security notes

- Bot never fetches raw URLs — only TinyFish Fetch, with retry/backoff.
- Citations are mechanically restricted to the verified pool; the validator
  is injection-tested (bogus URLs in the LLM output are dropped).
- Secrets live in `.env` (gitignored); `Dockerfile` runs as non-root with
  read-only rootfs + tmpfs.
